# Feed and Sitemap Validation Results (Issue 63)

## Test Overview

Integration tests that validate RSS/Atom feeds and sitemaps produced by rustkyll
against Jekyll reference output for two real sites.

## Sites Tested

### DataTalksClub/datatalksclub.github.io
- **feed.xml**: Atom feed generated by rustkyll's programmatic feed generator
- **sitemap.xml**: Rendered from Liquid template or generated programmatically

### alexeygrigorev/kids-horror-stories-ru

- **sitemap.xml**: Programmatically generated (site has no sitemap template)

### Known Issues Found

1. **Feed Liquid tag leakage**: Both DTC feed.xml and kids podcast.xml contain raw Liquid tags (`{{`, `{%`). This suggests the feed content (post body HTML) is not being fully rendered before inclusion.
2. **Podcast template iteration**: The kids podcast.xml Liquid template only produces 1 `<item>` instead of iterating over all 1343 stories. The `for` loop over `site.stories` is not expanding correctly.
3. **Slug generation**: Two sitemap URLs have malformed slugs containing spaces instead of hyphens (e.g., `hybrid search` instead of `hybrid-search`, ` aashishnair` with leading space).

## How to Run

```bash
# Unit tests only (fast, runs in default suite)
cargo test --test integration_feed_sitemap

# All ignored integration tests (slow, builds real sites)
cargo test --test integration_feed_sitemap -- --ignored --nocapture

# Specific test
cargo test --test integration_feed_sitemap -- --ignored test_dtc_feed_validation
```

## Notes

- All integration tests are `#[ignore]` to keep the default test suite fast
- Jekyll must be installed for comparison tests (`*_vs_jekyll`)
- Validation-only tests (`*_validation`) only require rustkyll
- 5% tolerance accounts for minor differences in edge case handling
- 90% overlap threshold for feed title matching accounts for max_posts limits
- The `test_dtc_feed_vs_jekyll` test gracefully skips if Jekyll does not produce feed.xml (requires jekyll-feed plugin)
