# Issue 268: JSON-LD description entity escaping and smart quotes

## Problem

On ~157 DTC podcast/post pages, JSON-LD `about[].description` fields differ from Jekyll output. The description values come from the DTC templates in `_layouts/post.html` and `_layouts/podcast.html`, which use patterns like:

```liquid
{% if author.bio_short %}{{ author.bio_short | strip_html | jsonify }}{% else %}{{ author.content | strip_html | jsonify }}{% endif %}
```

And in `_layouts/author.html`:
```liquid
{%- assign person_description = page.bio_short | default: page.description | default: content | strip_html | strip_newlines | truncate: 200 -%}
"description": {{ person_description | jsonify }}
```

Three root causes produce the mismatches, plus one downstream effect:

### 1. HTML entity preservation in strip_html (13 cases)

When collection content (e.g., a person's bio) contains `&` in the markdown source, kramdown renders it as `&amp;` in HTML. Jekyll's `strip_html` removes tags but preserves `&amp;` as a literal string. Then `jsonify` embeds `&amp;` in the JSON string. Rustkyll produces `&` instead.

**Example** (from `podcast/analytics-to-data-science-with-kaggle-portfolio.html`):
- Jekyll: `"...Ambassadors for Z by HP &amp; NVIDIA..."`
- Rustkyll: `"...Ambassadors for Z by HP & NVIDIA..."`

**Root cause investigation needed**: Determine whether rustkyll's content pipeline decodes HTML entities before `strip_html` runs, or whether the markdown renderer produces `&` instead of `&amp;` for the `_people` collection content. The `strip_html` filter itself (in `vendor/liquid-lib/src/stdlib/filters/html.rs`) only does regex tag removal and does NOT decode entities, so the issue is upstream.

### 2. Smart/curly quotes in collection content (33 cases)

Jekyll's kramdown converts straight apostrophes (`'`, U+0027) to right single quotes (`'`, U+2019) in rendered HTML. When `strip_html` removes tags, the curly quotes survive into the description. Rustkyll outputs straight apostrophes instead.

**Example** (from `podcast/algorithms-data-structures-for-engineers.html`):
- Jekyll: `"He\u2019s the author of..."` (curly right single quote)
- Rustkyll: `"He's the author of..."` (straight apostrophe)

**Example** (from `podcast/building-data-products-lead-data-scientist.html`):
- Jekyll: `"easyJet\u2019s Data Science..."` (curly)
- Rustkyll: `"easyJet's Data Science..."` (straight)

**Root cause**: The `_people` collection markdown content is rendered with kramdown smart quotes in Jekyll. Rustkyll's collection content rendering may not apply smart punctuation, or `page.content` / `author.content` in the template context may use a pre-rendered (non-smart-quoted) version. Note: rustkyll already has smart quote support in `src/kramdown.rs` (`fix_smart_quote_directions`, `apply_kramdown_smart_quotes_to_straight`) -- the issue is whether this is applied to collection document content that gets exposed as `author.content` in templates.

### 3. Trailing newline in short descriptions (18 cases)

When a person's bio is short enough that `strip_html` produces text shorter than the 200-char truncation limit, Jekyll preserves a trailing `\n` from the content. Rustkyll trims it.

**Example** (from `podcast/chief-data-officer-data-strategy-and-org-design.html`):
- Jekyll: `"Marco is the Chief Data Officer at OLX Group. Before that, he worked at Spotify, Twitter, and Facebook.\n"`
- Rustkyll: `"Marco is the Chief Data Officer at OLX Group. Before that, he worked at Spotify, Twitter, and Facebook."`

**Root cause**: Likely the content string stored in the collection document has its trailing whitespace stripped somewhere in rustkyll's processing pipeline before it reaches the template.

### 4. Description truncation mismatch (98 cases, downstream)

Both sides truncate to 200 characters, but because issues 1-3 change the character content, the 200-char window cuts at different positions. Fixing issues 1-3 will automatically fix most of these.

## Scope

This issue covers only the `about[].description` field in JSON-LD `<script type="application/ld+json">` blocks generated by DTC's layout templates (`_layouts/post.html`, `_layouts/podcast.html`, `_layouts/author.html`). It does NOT cover:
- JSON-LD `endDate`/`startDate` formatting (that is issue #267)
- JSON-LD `transcript` diffs (separate issue)
- Non-JSON-LD DOM diffs (paragraph wrapping, etc.)

## Test Scenarios

### Unit: HTML entity preservation through strip_html | jsonify

- Input HTML: `<p>HP &amp; NVIDIA</p>`, apply `strip_html | jsonify`, verify output contains `"HP &amp; NVIDIA"` (entity preserved)
- Input HTML: `<p>3 &lt; 5</p>`, apply `strip_html | jsonify`, verify output contains `"3 &lt; 5"` (entity preserved)
- Input with no entities: `<p>Hello World</p>`, apply `strip_html | jsonify`, verify output is `"Hello World"` (no change)

### Unit: Smart quotes in collection content through strip_html | jsonify

- Markdown source `He's a developer` rendered through kramdown, then `strip_html | jsonify` must produce JSON string with U+2019 (`He\u2019s`)
- Markdown source `It's great` rendered through kramdown, then `strip_html | jsonify` must produce curly apostrophe
- Non-ASCII content with apostrophes (e.g., `Platanomel\u00f3n's mission`) must also get smart quotes

### Unit: Trailing newline preservation

- Content `<p>Short bio text.</p>\n` through `strip_html | jsonify` must produce `"Short bio text.\n"`
- Content with multiple trailing newlines should preserve them as kramdown would
