# Issue 260: Fix JEKYLL_FAIL sites by adding bundle install to recount script

## Problem

13 sites show JEKYLL_FAIL in the DOM recount results because the recount script (`scripts/recount-all-dom.sh`) does not run `bundle install` before building with Jekyll. The script checks for `Gemfile.lock` and uses `bundle exec jekyll build`, but the gems are never actually installed first.

Investigation reveals three categories of JEKYLL_FAIL sites:

### Category A: Fixable with bundle install (3 sites)

These sites build successfully after `bundle install` (or `bundle update`):

| Site | Notes |
|------|-------|
| jekyll-vitepress-theme | `bundle install` then `bundle exec jekyll build` works |
| jekyll-theme-chirpy | `bundle install` then `bundle exec jekyll build` works |
| minimal-mistakes | Needs `bundle install` (json gem version conflict resolves itself); builds with Sass deprecation warnings but succeeds |

### Category B: Fail even after bundle install (7 sites)

These have deeper issues -- Ruby version mismatches, missing native extensions, missing external build steps, or deprecated Jekyll features:

| Site | Failure Reason |
|------|---------------|
| minima | `bundle install` works but Jekyll fails: missing `seo` tag (jekyll-seo-tag plugin not loaded) |
| made-mistakes-jekyll | `bundle install` works but Jekyll fails: missing `jekyll/tagging` plugin dependency |
| uswds-site | `bundle install` works but Jekyll fails: needs external USWDS library build step (`build:html`) |
| bitcoin-org | Gemfile requires Ruby 2.5.8, system has 3.3.7 |
| homebrew-site | Gemfile requires Ruby 4.0.1 (future version) |
| edition-template | Bundler 1.16.4 incompatible with Ruby 3.3 (`untaint` removed) |
| programming-historian | `bundle install` fails: nokogumbo native extension build failure |

### Category C: No Gemfile at all (3 sites)

These have no Gemfile and fail with plain `jekyll build` due to deprecated features:

| Site | Failure Reason |
|------|---------------|
| hyde | Uses deprecated `relative_permalinks: true` (removed in Jekyll 3+) |
| wtf-html-css | Uses deprecated `redcarpet` markdown engine and `pygments` highlighter |
| jekyll-docs/lib/site_template | ERB template with `<%= Time.now %>` in post date -- not a real site |

## Goal

1. Add `bundle install` to the recount script so Category A sites (3 sites) get real DOM comparison numbers.
2. For Category B and C sites that still fail Jekyll builds, run rustkyll-only validation and report useful metrics instead of bare "JEKYLL_FAIL".

## Scope

This issue modifies ONLY `scripts/recount-all-dom.sh` and the results output format. No Rust code changes.

## Implementation Details

### Part 1: Add bundle install before Jekyll build

In the Jekyll build section of `recount-all-dom.sh`, add a `bundle install` step when a `Gemfile` exists (not just `Gemfile.lock`). The current script only checks for `Gemfile.lock` on line 86:

```bash
if [[ -f "$src_dir/Gemfile.lock" ]]; then
```

Change the logic to:
1. If `Gemfile` exists, run `bundle install --quiet` first (with timeout)
2. Then use `bundle exec jekyll build` (as it does now for Gemfile.lock sites)
3. If only `Gemfile` exists (no `Gemfile.lock`), also use `bundle exec jekyll build` after install

### Part 2: Rustkyll-only validation for JEKYLL_FAIL sites

When Jekyll build fails, instead of immediately recording `JEKYLL_FAIL` and continuing, still attempt to build with rustkyll. If rustkyll succeeds, report:
- Number of HTML pages generated by rustkyll
- Number of files with liquid leaks (`{{` or `{%` in output)
- Number of empty HTML files (0 bytes)

The results table row for these sites should show something like:

```
| hyde | JEKYLL_FAIL | 5 pages (rustkyll-only) | 0 |
```

Instead of the current:

```
| hyde | JEKYLL_FAIL | - | - |
```

### Part 3: Results table format

The output format for JEKYLL_FAIL sites changes from:

```
| site | JEKYLL_FAIL | - | - |
```

To one of:
- `| site | JEKYLL_FAIL | N pages (rustkyll-only) | L |` -- if rustkyll builds successfully (N = page count, L = liquid leaks)
- `| site | BOTH_FAIL | - | - |` -- if both Jekyll and rustkyll fail

## Acceptance Criteria

- [ ] `recount-all-dom.sh` runs `bundle install --quiet` when a `Gemfile` exists in the site directory, before attempting the Jekyll build
- [ ] The `bundle install` step has a timeout (60 seconds) so it does not hang
- [ ] Sites with `Gemfile` but no `Gemfile.lock` also use `bundle exec jekyll build` (not plain `jekyll build`)
- [ ] After the script change, jekyll-vitepress-theme, jekyll-theme-chirpy, and minimal-mistakes produce DOM comparison numbers (no longer JEKYLL_FAIL)
- [ ] Sites where Jekyll still fails (Category B and C) show rustkyll-only stats in the results table: page count and liquid leak count
- [ ] Sites where both Jekyll AND rustkyll fail show "BOTH_FAIL" instead of "JEKYLL_FAIL"
- [ ] No regressions on the 35 sites that already had DOM comparison numbers (run the full recount and verify totals are the same or better)
- [ ] The script still works correctly with `--site` flag for a single site

## Notes

- `bundle install` can be slow (network I/O for downloading gems). The 60-second timeout per site is a safeguard.
- Some sites may need `bundle update` rather than `bundle install` to resolve version conflicts. Start with `bundle install`; if that fails, the site falls into the JEKYLL_FAIL-with-rustkyll-only-stats bucket.
- The `jekyll-docs/lib/site_template` directory is a scaffolding template with ERB placeholders, not a real Jekyll site. It will always fail both Jekyll and rustkyll. It is acceptable for this to show BOTH_FAIL.
